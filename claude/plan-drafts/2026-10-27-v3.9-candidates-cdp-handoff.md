## Five findings (section 9 format)

### F1 BUG: the OP4/OP5 finalizer has nothing to clean up
- **What:** Section 6.10 says "a finalizer deregisters the gate in PRCP on delete", but the controller contract never registers anything; the reconcile only reads the GateDecision. Pick one at Nov 15: (a) the controller registers the gate in PRCP with an idempotent call keyed by the ReleaseGate's UID, adds its finalizer before that call, and on delete treats "already gone" as success and retries any real failure; or (b) drop the PRCP obligation and give the finalizer lesson a small fixture with an explicit cleanup job.
- **Why:** a finalizer that protects nothing teaches the wrong model. The OP5 cold question "what does your finalizer protect?" would have no honest answer.
- **Evidence:** v3.8 section 6.10, the controller contract paragraph.
- **Time cost:** (a) about 1.5h (one PRCP endpoint with its Python test, plus the controller call) inside OP4/OP5; (b) about 0.5h. Both land in W54-W60 (Oct-Nov 2027); the checker sets the date effect at rebuild.
- **Risk reduced:** a wrong mental model in the one controller Om will defend in interviews.

### F2 GAP: in A2, a failed probe must not cancel the other probes
- **What:** add to A2's content and proof: a target that is down becomes a `ProbeResult` with its failure reason, never a returned error; only an execution fault (bad config, shutdown) returns an error. Add one test: one target down, every other target still reports. Add the cold question "should one failed probe cancel all the others?"
- **Why:** with `errgroup.WithContext`, the shared context is cancelled the first time any function returns a non-nil error (pkg.go.dev, fetched Oct 27). Writing `return err` for a down target quietly cancels the healthy probes, and `-race` would not catch it.
- **Time cost:** +0.25h in A2 (W31-W34).
- **Risk reduced:** wrong data-plane results that green tests hide.

### F3 GAP: OP6 proof must show the envtest tests ran, and test a stale decision
- **What:** (i) OP6's fresh-clone proof shows a verbose run where the envtest cases actually ran, not skipped (envtest needs its binaries, and suites often skip without them); (ii) one test: the spec changes while the PRCP call is in flight, and the old answer is never written with the new `observedGeneration`; (iii) in OP1, teach what envtest cannot prove: it runs only etcd and the API server, no built-in controllers, so owner-reference garbage collection never happens and namespace deletion is not supported (Kubebuilder envtest reference, fetched Oct 27).
- **Why:** OP6 now says only "suite green on a fresh clone". A green suite with skipped tests would pass safeguard 10 while proving nothing.
- **Time cost:** +0.5h in OP6, +0.25h in OP1.
- **Risk reduced:** a false PASS by the coach, and a controller that writes stale status.
