# Office tasks: squeeze every task for yourself

Version 3, Oct 27 2026. Office time only, zero plan hours. IBM needs the code on time. Om needs four things from every task: skill, CV proof, a story, and numbers.

1. **Pick well.** When there is a choice, take the task with ownership, a design decision, debugging, cross-team work or a number you can measure. Review teammates' PRs when you can: free code reading, and a code-review story.
2. **Decide first.** Before the AI codes, write your approach and one option you rejected. That choice is the senior signal, and it is yours.
3. **Learn from the diff.** Do the task with an IBM-approved AI tool, then ask it: "Teach me every Go and Kubernetes idea in this diff, one at a time, each with a tiny example I run."
4. **Own it before the PR.** Be able to explain every changed line and one way it could break; write the test cases and the PR description yourself. Hard deadline: ship anyway, and learn it within the week.
5. **Measure it.** Note the before and after numbers (time, cost, failures, manual effort) and, after rollout, what production showed.
6. **Write it the same day,** in a private file, in your own words: the problem, your decision and the rejected option, what you wrote and what the AI wrote, the failure case, the result. Detail fades in days. This is your CV line, interview story and promotion case. No IBM code in it.
7. **Send one cleaned line to the Phase 1 coach.** The coach checks you can explain it cold and logs it against the 2 owned changes and the 7 stories (plan section 6.8).
